## 1. Start here

Read the root README and relevant guides in `docs/`. Check [Known Limitations](docs/KNOWN_LIMITATIONS.md) and existing issues before opening a new request.

## 2. Bug reports

Use the Bug Report issue template. Include the affected package, operating system, Node.js/npm versions, browser, command, expected result, actual result, and sanitized logs.

## 3. Feature requests

Use the Feature Request template. Explain the user problem, proposed behaviour, alternatives, and security or accessibility impact.

## 4. Security reports

Do not use public issues for vulnerabilities or exposed secrets. Follow [SECURITY.md](SECURITY.md) and use private vulnerability reporting where available.

## 5. Information to provide

Include a concise title, exact reproduction steps, relevant file path, expected and observed behaviour, sanitized screenshots or logs, and whether the issue is repeatable. Remove all credentials and personal data.

## 6. Support boundaries

This is a community-maintained project. No guaranteed response time or commercial support agreement is offered. Never share passwords, API keys, customer records, payment details, or production database exports in support requests.
